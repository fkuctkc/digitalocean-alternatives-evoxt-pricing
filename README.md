## DigitalOcean 的账要按哪几项算

在决定换不换之前，先把 DigitalOcean 的计费口径摆清楚，否则很容易拿“$4 起”去比别人的“$11.99”，比错了对象。

DigitalOcean 的 Basic Droplet 阶梯是 512 MiB $4、1 GB $6、2 GB $12、2 核 4 GB $24。1 GB 档给 1 vCPU、25 GiB SSD、1,000 GiB 出站流量；2 核 4 GB 档给 80 GiB SSD 和 4,000 GiB 流量。超出套餐的流量按 $0.01/GiB 计。

计费粒度是它容易被低估的一项。**按秒计费从 2026 年 1 月起生效，带 60 秒最低计费**。跑几分钟的构建任务、压测、临时环境，成本按秒结算，不再被凑整到一小时。官方举过的例子是 4 vCPU / 8 GiB 的机器跑 5 分钟约 $0.006，旧的小时计费口径下约 $0.07。CI、一次性任务、短周期测试这类场景，这个差别比月单价更明显。

新账户有 $200 信用额度，有效期 60 天，需要绑定信用卡或 PayPal，60 天到期或额度用尽后开始正常扣费。它的作用是让你把真实负载跑满两个月再判断，而不是看一篇文章就搬家。

附加项也要算进去：快照 $0.06/GB/月；备份按 Droplet 费用的 20%（周备）或 30%（日备），也可以走用量计费；Reserved IP 绑定到 Droplet 时免费；防火墙、DNS、VPC、容器registry（1 个仓库 / 500 MiB）、Functions（每月 90,000 GiB-seconds）都在基础价内。

托管数据库是 DigitalOcean 相对 Hetzner 这类厂商的核心差异。单节点 Standard PostgreSQL 1 GiB 内存档约 **$15.15/月**，覆盖 PostgreSQL、MySQL、MongoDB、Kafka 和缓存；DOKS 提供免费控制面选项，高可用另付费；平台覆盖 13 个 region、20 个数据中心、16 个可新建 Droplet 的位置。

所以“DigitalOcean 贵不贵”这个问题没有统一答案。只买一台裸 VM，它比 Hetzner 贵，比 Evoxt 贵一倍；一旦把托管数据库、Spaces、DOKS、多区域部署折算进去，它省掉的是你自己装 PgBouncer、自己搭 Kubernetes、自己维护备份的时间和出错概率。

## 从 DigitalOcean 搬走要动的东西

DigitalOcean 的产品建在标准开源原语上：Linux 虚拟机、标准 PostgreSQL / MySQL、S3 兼容对象存储、上游 Kubernetes。应用很少绑死专有 API，代码基本不用重写，一次计划内维护窗口就能把流量切过去。这不等于零停机，也不等于半小时搞定。

**动手前先清点四类资产：**

1. Droplets 的规格、CPU 和内存占用曲线、盘上有哪些不来自镜像的本地数据。
2. 托管数据库的引擎和版本（比如 PostgreSQL 15、MySQL 8）、库的总大小、装了哪些扩展。
3. Spaces 的桶数量、总容量、ACL 是公开还是私有、有没有挂内置 CDN。
4. Cloud Firewall 规则、VPC 网段划分、负载均衡的健康检查路径和间隔。

**切换前几天把 DNS 的 TTL 降到 60 或 300 秒。** 这一步经常被拖到当天才想起，然后发现 TTL 是 3600，回滚要等一小时生效。

**用 Terraform 或 OpenTofu 重建，不要复制旧 VM 的磁盘快照。** UpCloud、Scaleway、Hetzner 都有官方 provider。新云上开一台干净的 Linux VM，重新部署代码，把配置从 IaC 里重建。旧镜像搬过去会把旧内核、旧驱动、旧云代理一起带过去，后面出问题很难定位。

**维护窗口内的操作顺序：**

1. 应用进维护模式或只读模式，停掉所有写入。
2. 确认数据库复制延迟归零（逻辑复制或物理复制都行）。
3. 用 `rclone` 做最后一次对象存储同步，此前已经全量同步过一次，这次只补增量。
4. 提升新库为主库，切换应用连接串。
5. 改 DNS 记录，或改 Cloudflare、bunny.net 这类代理的目标源站。
6. 观察错误率和延迟，跑一遍关键路径。
7. 旧环境保留一到两周，期间必要时配反向复制以便快速回滚，确认稳定后再删资源、停账单。

数据库搬迁用 `pg_dump` / `pg_restore` 就够，几 GB 的库在维护窗口内完成没有压力；上百 GB 的库要考虑提前做逻辑复制预热，别把全量导入压在窗口里。

## 四个最容易在迁移夜出问题的地方

这四个坑的共同点是：代码能跑、服务能起，但某个环节静默失效，等发现时已经过了回滚窗口。

**1. 数据库里存了完整的 Spaces URL。** DigitalOcean Spaces 的地址形如 `bucket.region.digitaloceanspaces.com` 或 `cdn.digitaloceanspaces.com`。如果当初图省事把完整 URL 写进了数据表，换云之后所有图片和附件链接全部指向旧域名。处理方式两种：跑一个数据库迁移脚本批量替换字符串，或者干脆给对象存储绑一个自定义域名，以后换云只改 DNS，URL 永远不动。第二种更省事，值得在迁移时一次性做掉。

**2. 启动脚本查询 169.254.169.254 的专有 JSON 路径。** DigitalOcean 的 metadata 服务返回的是自家格式的 JSON。UpCloud、Scaleway、Hetzner 用的是标准 `cloud-init`，路径和字段名都不一样。用了 metadata 做初始化配置的机器，换过去会拿到空值，然后带着错误的 hostname 或缺失的 SSH key 启动。迁移前把这类脚本全部搜出来，改成 `cloud-init` 标准格式。

**3. 连接池要自己补。** DigitalOcean 托管数据库的控制面板里内置 PgBouncer，连接池是开箱可配的。UpCloud 和 Scaleway 有托管池选项，Hetzner 上没有，得在 PostgreSQL 旁边自己装一个 PgBouncer 并调好 `pool_mode` 和连接数上限。应用侧连接数写得比较激进的项目，少了这一层会直接把数据库连接打满。

**4. 25 / 465 / 587 端口默认被封。** DigitalOcean、UpCloud、Scaleway、Hetzner 对新账户的出站 SMTP 端口都有默认封锁，防垃圾邮件。如果服务器直接发信，或者要通过这几个端口连 SMTP relay，必须**在迁移之前**提交工单申请解封，或者改用邮件服务商的 HTTP API、2525 端口。迁移当晚才发现发不出邮件，找回密码、告警通知、订单确认会一起哑掉。

前三条花半天能排查完，第四条要等工单，提前一周提最稳。

## 哪些情况建议别折腾

有几类用法，迁移省下的钱不足以覆盖风险，留在原地更划算。

**重度使用 App Platform 的。** App Platform 没有持久卷，本地文件系统上限 4 GiB 且每次重新部署就清空，CPU 自动扩缩需要专用 CPU 套餐，镜像必须是 AMD64 Linux，低价的 dev 数据库不能跨区迁移。这些限制在迁到普通 VPS 之后不但不会消失，反而要你自己实现一套部署流水线。替代路径是 Render（有持久磁盘，`render.yaml` 和 App Platform 的 app spec 结构接近）、Railway、Fly.io 或 Cloud Run，都是 PaaS 层的东西，不是换台便宜的 VPS 能解决的。

**依赖 DOKS 免费控制面的。** Hetzner 没有一方托管的 Kubernetes，得自己在 Cloud Server 上跑 k3s 或 Talos。省下的钱要拿运维工时换，节点多了不划算。

**要托管 MongoDB 或 Kafka 的。** Hetzner 和 Evoxt 都没有对应产品，这两个组件自建的复杂度远高于 PostgreSQL。

**需要 13 个 region 覆盖的。** DigitalOcean 的 20 个数据中心、16 个可新建 Droplet 的位置，是它相较中小厂商最实的一块资产。用户分布在多个大洲、要做就近接入的项目，换到机房数量少的厂商会直接体现在延迟上。

## 欧盟合规与出口费的两个时间点

如果你的公司在欧盟，或者客户要求 GDPR / DORA 合规，有两件事值得知道。

**出口费**：按 EU Data Act（Regulation (EU) 2023/2854），迁移产生的出口费在 **2027 年 1 月 12 日**之前被限制在提供商的成本水平，此后在欧盟范围内全面禁止。也就是说现在搬迁还要付一部分流量费，一年多之后这笔钱就没有了。如果迁移不着急，时间点可以纳入考虑。

**DORA**：《数字运营韧性法案》自 **2025 年 1 月 17 日**起适用，受约束的金融机构需要一份有文档的 ICT 退出策略。用 Terraform 定义的标准开源基础设施，本身就是这份文档里最容易写清楚的一段——资源清单在代码里，重建步骤可复现，不依赖某家厂商的专有服务。

另外一层现实考虑是币种：欧洲公司付美元有汇兑成本和月度账目波动，UpCloud、Scaleway、Hetzner 都以欧元结算，总部在芬兰、法国、德国，数据中心在欧盟境内。Evoxt 以美元计价，这一点对需要欧元账期报销的团队是个小摩擦。

## 怎么定：三种情况三种选法

**只要能跑应用的便宜 Linux 机器，数据库自己管。** Evoxt 的 VM-2 是这一档里价格最有优势的选择之一，2 核 4 GB 卖 $11.99，同档 DigitalOcean 是 $24。前提是你的存储和流量需求不超过 30 GB / 600 GB，超了就要往上加档，价格优势会收窄。VM-0.75 适合轻量服务，VM-3 适合 4 核但内存吃得不多的并发型负载。

**在用托管 PostgreSQL、Spaces、DOKS 中的任意两项。** 算一下自建这几样要多少工时，多数小团队算完会留在 DigitalOcean，或者转向托管服务更全的方向。省下的月费抵不上一次数据库故障的排查时间。

**有欧盟合规要求或欧元账期需求。** 优先看欧盟境内的厂商，出口费政策和 DORA 的时间点都在往对迁移有利的方向走。
